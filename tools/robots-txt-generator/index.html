    Robots.txt Generator guide

    How a compliant crawler chooses a rule

    Rules are grouped under User-agent lines. A crawler prefers a group naming its own product token over the `*` wildcard group; rules from less-specific groups are not merged just because they look relevant. It then compares the URL path (including query string) with that group’s Allow and Disallow patterns. The tester on this page follows the widely used longest-match behaviour and supports `*` as a wildcard plus a trailing `$` to anchor the end of a path.

    Useful starting patterns

    GoalExample ruleWhat happens
    Allow everythingUser-agent: * Disallow:No path is blocked by robots.txt.
    Block a private areaUser-agent: * Disallow: /private/Compliant crawlers do not fetch paths beginning /private/.
    Make one exceptionDisallow: /private/ Allow: /private/public/The longer Allow pattern wins for the public subpath.
    Block one named crawlerUser-agent: ExampleBot Disallow: /Only ExampleBot’s group is blocked; other crawlers use their own or wildcard group.

    Mistakes that quietly damage crawling

    • Treating robots.txt as secrecy: anyone can read it, and listing a sensitive path can advertise that path. Protect the resource itself.
    • Copying a staging-site “Disallow: /” to production. Test the home page and a key landing page before every publish.
    • Blocking CSS, JavaScript or images a page needs for rendering; a crawler may then see a broken or misleading page.
    • Using a relative Sitemap value. Give the complete absolute URL, for example https://example.com/sitemap.xml.
    • Expecting Crawl-delay to control Googlebot. Google does not support that directive, although some other crawlers may honour it.
    • Trying to remove an indexed page with Disallow alone. Use noindex or proper access control as described in the FAQs.

    Frequently asked questions

    Does Disallow remove a page from Google?

    Not reliably. Robots.txt controls crawling, not indexing: a blocked URL discovered from links can still appear in results without its content being crawled. To keep a public page out of search, allow crawling and use a noindex tag/header so the crawler can see it. For genuinely private material, use authentication — robots.txt is public and is not a security control.

    Which rule wins, Allow or Disallow?

    The crawler first uses the most specific matching user-agent group instead of the wildcard group. Inside that group, the longest matching Allow/Disallow pattern normally wins; on an exact tie, the least restrictive result (Allow) is used. The tester above shows the winning rule for the current draft.

    Where does robots.txt go?

    At the root of the exact protocol and host it should govern — for example https://example.com/robots.txt. A file under /blog/robots.txt is ignored as a robots file, and www, non-www and subdomains are separate hosts.

    Will the AI-crawler preset block search engines?

    It is designed not to: named AI training/data crawlers get Disallow: /, while the wildcard group remains open for ordinary crawlers. Only robots that choose to obey robots.txt will comply, so it is a preference signal, not access control.
